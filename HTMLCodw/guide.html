1. Complete Tech Stack Overview

The Citizen Service Navigator uses a modern, lightweight tech stack designed for performance, scalability, and ease of development.

1.1 Backend Stack

Python 3.10+ 🐍

  • The primary programming language for all backend logic
  • Chosen for readability, vast ecosystem, and AI/ML capabilities
  • Handles request processing, NLP, business logic, and database operations

FastAPI ⚡

  • Modern Python web framework for building REST APIs
  • Advantages: Automatic API documentation, Pydantic integration, async support, high performance
  • Provides endpoints like /api/register, /api/chat, /api/eligibility
  • Type hints reduce bugs and improve developer experience

Uvicorn 🚀

  • ASGI server that runs the FastAPI application
  • Serves the backend on a specified host and port
  • Lightweight and fast, ideal for async Python code

SQLAlchemy 🗄️

  • ORM (Object-Relational Mapper) for Python
  • Allows defining database tables as Python classes
  • Handles queries without writing raw SQL
  • Compatible with both SQLite (development) and PostgreSQL (production)

Pydantic ✅

  • Data validation library integrated with FastAPI
  • Auto-validates incoming request data (emails, passwords, types)
  • Generates clear error messages for invalid data

SQLite (Development) / PostgreSQL (Production)

  • SQLite: File-based database, zero setup, perfect for prototypes
  • PostgreSQL: Scalable relational database for production environments
  • SQLAlchemy code works with both without changes

1.2 AI/ML Components

Custom NLP Engine (Rule-Based)

  • Understands user input without external APIs
  • Detects user intent (scholarship, job, certificate, etc.)
  • Extracts entities (age, state, income, category, education level)
  • Uses pattern matching and keyword extraction
  • Advantages: No API costs, offline capability, data privacy, fast response

Rules Engine (Eligibility)

  • Evaluates whether users qualify for government schemes
  • Logic example: "If age > 18 AND income < 200000 AND category = OBC → eligible"
  • Returns status: eligible, potentially eligible, missing info, or not eligible

Compatibility Scoring Algorithm

  • Multi-factor scoring system (0-100%)
  • Weighted calculation: Profile match (60%), Document readiness (30%), Priority alignment (10%)
  • Visualized with animated progress meters in the UI

1.3 Frontend Stack

Vanilla HTML5

  • Semantic markup for structure
  • Single index.html file with multiple sections
  • No framework dependencies for fast loading

Modern CSS3 (Glassmorphism)

  • Glassmorphism: Frosted-glass effects using backdrop-filter: blur()
  • Gradients: linear-gradient(135deg, #FF9933, #FF6B00)
  • Animations: @keyframes with cubic-bezier() easing
  • Responsive Design: @media queries for mobile compatibility
  • Custom Scrollbars: Styled scrollbar components

Vanilla JavaScript (ES6+)

  • No React, Vue, or Angular — pure JavaScript for speed and simplicity
  • Fetch API: Communicates with backend endpoints
  • DOM Manipulation: Dynamically renders chat messages and results
  • Web Speech API: Voice input functionality
  • Async/Await: Clean asynchronous code for API calls

Google Fonts (Inter + Space Grotesk)

  • Professional typography loaded via CDN
  • Inter for body text, Space Grotesk for headings

2. Setup & Installation Guide

2.1 Prerequisites

  • Python 3.10 or higher installed on your system
  • pip (Python package manager) available
  • A modern web browser (Chrome recommended for voice features)
  • Basic familiarity with command line/terminal

2.2 Step-by-Step Installation

Step 1: Create Project Folder

mkdir citizen_navigator
cd citizen_navigator

Step 2: Install Python Dependencies

pip install fastapi uvicorn sqlalchemy pydantic

Step 3: Create Required Files

Create the following files in your citizen_navigator folder:

FilePurpose
main.pyBackend entry point with all API endpoints
database.pySQLAlchemy ORM models for users, profiles, schemes
nlp_engine.pyNatural language processing logic
eligibility_engine.pyRules engine for scheme eligibility
pathway_engine.pyRoadmap generator for schemes and services
seed_data.pySample government schemes data
static/index.htmlFrontend HTML structure
static/style.cssGlassmorphism styling and animations
static/app.jsFrontend logic and API communication

Step 4: Run the Server

python main.py

You should see output similar to:

INFO:     Uvicorn running on http://127.0.0.1:8000
INFO:     Application startup complete.

Step 5: Open in Browser

http://localhost:8000
🎉 Success! The login screen should appear. Register a new account to start using the application.

2.3 Common Issues and Solutions

Issue: "ModuleNotFoundError"

Solution: Reinstall dependencies:

pip install fastapi uvicorn sqlalchemy pydantic

Issue: "Port 8000 already in use"

Solution: Change the port in main.py:

uvicorn.run(app, host="0.0.0.0", port=8080)

Issue: "Database is locked"

Solution: Delete the database file and restart:

del citizen_navigator.db
python main.py

Issue: "No module named 'database'"

Solution: Ensure you're in the correct directory:

cd citizen_navigator
python main.py

3. Local Hosting & Sharing

There are three primary methods to share your locally-running application with teammates or external users.

3.1 Method 1: Same Wi-Fi Network (Easiest, Free)

Best for: Teammates in the same office or connected to the same Wi-Fi network.

Requirements:

  • All computers must be on the same network
  • Firewall must allow inbound connections on port 8000

Step 1: Find Your Computer's IP Address

On Windows:

ipconfig

Look for "IPv4 Address" — it will look like 192.168.1.5 or 10.0.0.5

On Mac/Linux:

ifconfig
# or
ip addr show

Step 2: Update main.py to Bind to All Interfaces

Find the bottom of your main.py file:

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)

Replace it with:

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)

Step 3: Configure Firewall (Windows)

Option A: GUI Method

  1. Press Win + R, type wf.msc, press Enter
  2. Click "Inbound Rules" → "New Rule"
  3. Select "Port" → Next
  4. TCP, Specific port: 8000 → Next
  5. "Allow the connection" → Next
  6. Apply to all profiles → Name it "Citizen Navigator" → Finish

Option B: PowerShell Command (Run as Administrator)

New-NetFirewallRule -DisplayName "Citizen Navigator" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow

Step 4: Share the Link

Teammates enter this URL in their browser:

http://YOUR_IP_ADDRESS:8000

Replace YOUR_IP_ADDRESS with your actual IP (e.g., http://192.168.1.5:8000).

✓ Done! Anyone on the same Wi-Fi can now access your application.

3.2 Method 2: Public Link via ngrok (Best for Demos)

Best for: Worldwide demos, external sharing, presentations.

ngrok creates a public URL that anyone can access from anywhere in the world.

Step 1: Install ngrok

Download from: https://ngrok.com/download

Or via package manager:

# Chocolatey (Windows):
choco install ngrok

# Homebrew (Mac):
brew install ngrok

Step 2: Get Your Auth Token

  1. Visit https://dashboard.ngrok.com/get-started/your-authtoken
  2. Sign up for a free account
  3. Copy your auth token

Step 3: Configure ngrok

ngrok config add-authtoken YOUR_TOKEN_HERE

Step 4: Start Your Application

python main.py

Step 5: Run ngrok in a New Terminal

ngrok http 8000

You'll see output similar to:

Session Status      online
Forwarding         https://a1b2c3d4.ngrok-free.app → http://localhost:8000

Step 6: Share the Public Link

Share this URL with anyone:

https://a1b2c3d4.ngrok-free.app
✓ Done! Anyone in the world can now access your application via this link.

3.3 Method 3: LocalTunnel (No Signup Required)

Step 1: Install LocalTunnel

npm install -g localtunnel

Step 2: Start Your Application

python main.py

Step 3: Run LocalTunnel

lt --port 8000

You'll receive a URL like:

https://random-name.loca.lt

4.1 30-Second Project Pitch

The tech stack is Python FastAPI backend with SQLAlchemy ORM, vanilla HTML/CSS/JS frontend with glassmorphism design, and a custom rule-based AI that runs entirely offline — no API costs, full data privacy."

4.2 Common Interview Questions & Answers

Q1: What tech stack did you use?

A: I used Python FastAPI for the backend with SQLAlchemy for ORM and SQLite for storage. The frontend is vanilla HTML, CSS, and JavaScript with glassmorphism design. For AI, I built a custom rule-based NLP engine that doesn't require any external APIs — everything runs locally.

Q2: Why FastAPI over Flask or Django?

A: FastAPI is faster, has automatic API documentation, built-in type validation via Pydantic, and native async support for handling multiple users concurrently. It's more modern and the type hints catch bugs at development time.

Q3: How does your AI work without ChatGPT?

A: I built a custom rule-based NLP engine using pattern matching and keyword extraction. It detects user intent (scholarship, income certificate, etc.) and extracts entities (age, state, income, category). This approach has zero API costs, works offline, and keeps user data private. For more complex AI features, I can integrate OpenAI or Hugging Face models later.

Q4: What is glassmorphism?

A: It's a modern UI design trend using frosted-glass effects. I achieved it with backdrop-filter: blur() combined with semi-transparent backgrounds, creating a depth effect. It makes the UI feel modern and premium.

Q5: How does eligibility scoring work?

A: I use a multi-factor compatibility score:

  • Profile match (60% weight): Does user meet age/income/category/education criteria?
  • Document readiness (30%): How many required documents does user have?
  • Priority alignment (10%): Does user's need match scheme priority?

Total score is a weighted average, displayed as 0-100% with a visual meter.

Q6: How did you handle authentication?

A: I implemented token-based authentication using SHA-256 password hashing and stored auth tokens in HTTP-only cookies. Each request validates the token via a database lookup. Users get persistent profiles, saved chat history, and document progress.

Q7: Can this scale to handle many users?

A: Yes — the architecture is scalable:

  • FastAPI supports async for high concurrency
  • SQLAlchemy works with both SQLite (dev) and PostgreSQL (prod)
  • Frontend is CDN-friendly static files
  • For production, I'd deploy on Render/Railway/AWS with managed PostgreSQL

Q8: What was the hardest part of building this?

A: Two things:

  1. Designing the NLP engine without external APIs — I had to think carefully about Indian context (states, categories like OBC/SC/ST, education levels in Hindi/English).
  2. Reverse-engineering pathways — figuring out that for direct services (PAN card, bank account) you don't need scheme eligibility checks, just step-by-step guides. So I built two separate pathway engines.

Q9: How long did this take to build?

A: About [X hours/days] from concept to working prototype. The frontend styling took the longest because I wanted a premium glassmorphism look with smooth animations.

Q10: What would you improve next?

A: Three priorities:

  1. Deploy to cloud (Render/Railway) for 24/7 availability
  2. Integrate real OpenAI API for advanced NLP capabilities
  3. Add Hindi language support via internationalization (i18n)
